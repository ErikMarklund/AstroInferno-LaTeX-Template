\section{Origins}
\noindent
This template is for making third-party content for the Astro Inferno roleplaying game\footnote
{\url{https://astroinferno.com/}}. The template itself was derived
from the DnD5e LaTeX Template from the rpgtex
team\footnote{\url{https://github.com/rpgtex/DND-5e-LaTeX-Template}}. We are very
grateful for their exelent work, without which this template probably
would not have existed. Some DnD-specifc features have been removed,
other remain funcitonal but without documentation awaiting
resurrection, removal, or are just hidden but available for the more
adventurous TeXers. But most of all, the remaining features have been adapted
for Astro Inferno, and new features added, to enable
good-looking documents that mimic the styles seen in the Astro Inferno
Core Rulebook and various associated material such as Crown of Ruin.

The official Astro Inferno material employs a lot of advanced layout
features that require both expertise, specialised software, and manual
work (see for example the slanted column margins in the Core Rulebook).
This template will unfortunately never be able to reproduce or mimic
all such features, but we hope it will be a useful tool for producing
stunning campaign modules etc. Its key features plus some usefeul hacks are demonstrated here.
Making good looking running test with chapters, sections, etc. is quite straightforward.
To see how more complex things were accomplished, see the source code in |example.tex|.

\subsection{Technical Notes}
\paragraph{LATEX Engine}
Unlike the DnD5e LaTeX Template, this template was developed for LuaLaTeX.
As such, the template will probably not work with pdf2latex.
\paragraph{Prerequisites}
All required \LaTeX{} packages are included in the current TeX~Live.
Additional components, like fonts, are deistributed with the template.
\paragraph{Class vs. Package}
The parent template defines a class, but also works as a package that can be used in another document.
The development of this template however has focused on the class aspect, and has not been tested as a package.
As such, it is strongly recommended to use it as a class, like in this example document.

\section{Dark and Light}
The Astro Inferno rule book switches between light and dark pages, and
this template can do this too!
\subsection{Switching Mode}
Use |\AIMakeDark| and |\AIMakeLight| to
switch between the two styles. An optional argument providing an
alternative background image can be provided:\\[1em]
|\AIMakeDark{img/your_cool_image.jpg}|\\[1em]
Note that these commands will cause a page break. Thus, switching between the dark and
light modes should probably be introduced at a relatively late stage
in the qwriting process, when most of the content is finished,
as it will have notable implications for downstream typesetting.

|\AIMakeDark*| and
|\AIMakeLight*| suppress the page breaks, but should only be
used for initialisation in the preamble because of the layout problems
they cause if used mid document.

\subsection{New Background}
One can also insert a new background without switching mode using |\AIPlaceNewBackground|.
The starred version |\AIPlaceNewBackground*| will do the same, but for
one page only (e.g., p.~\pageref{ch:box_customisation}\footnote{Image taken at Skokloster castle}).
Both commands do \emph{not} cause a page break.

\subsection{Detecting Dark Mode}
The function |\AIIsDarkMode{}{}| can be used to detect if dark mode is
on. For example, |\AIIsDarkMode{yes}{no}|: \AIIsDarkMode{yes}{no}.
This is used above to choose between loading black or white logos
depending on whether dark mode is on or not.

We will switch to dark mode at the end of this page, insert a new background for a single page at the start of section~\ref{ch:images}, then switch back to light mode at
part~\ref{ch:weapons}.

\section{Text Boxes}
The module has three environments for setting text apart so that it is drawn to the reader's attention. |AIReadAloud| is used for text that a game master would read aloud.

\begin{AIReadAloud}[colback=AIdarkbox] % Not sure why its colour needs to be set explicitly.
  As you approach this module you get a sense that the blood and tears of many generations went into its making. A cold feeling descends upon you as you type your first words.
\end{AIReadAloud}

\subsection{As an Aside}
The other two environments are the |AIComment| and the |AISidebar|. The |AIComment| is breakable and can safely be used inline in the text.

\begin{AIComment}{This Is a Comment Box!}
  A |AIComment| is a box for minimal highlighting of text. It lacks the ornamentation of |AISidebar|, but it can handle being broken over a column.
\end{AIComment}

The |AISidebar| is not breakable and is best used floated toward a page corner as it is below.

\begin{AISidebar}[float=!b]{Behold the AISidebar!}
  The |AISidebar| is used as a sidebar. It does not break over columns and is best used with a figure environment to float it to one corner of the page where the surrounding text can then flow around it.
\end{AISidebar}

\section{Inline and Float Images}
Image placement in typesetting belongs in the $7^{th}$ level of hell.
The template uses twocolumn mode, which makes it even harder.
Floats that occupy a single column width often struggle to find a good
place, so images might be more easily placed as non-floats (like the
seal on p.~\pageref{fig:phenix}).
Floats that span two columns are possible, but
getting them rigth can be like grappling with Jörmungandr, in part
because of the many hidden |\clearpage|s lurking within various commands.
Sometimes it is better to
prepare a page-size image to use as a background image with
|\AIPlaceNewBackground*|.  On this page we do a dirty trick to place an
image\footnote{https://pixnio.com/nature-landscapes/underwater/jellyfish-aquarium-highlighted-green} independently of the text.
In addition to the jellyfish image, we have changed to a green version
of the standard dark-mode background image with
|\AIPlaceNewBackground*|.

\section{Image Page} \label{sec:imagepage}
There is a macro |\AIMakeElementImagepage{}{}| for making pages displaying
a single image.
An image must be provided with the |image| option. See other options
in table. The two arguments are for 'before-code' and 'after-code',

on image pages, but this can be changed by providing the option |suppressborder=false|.
|\AIMakeElementImagepage| was used to create the last page of
this document, and now we will use it to display the seal of Phenex
again.

\section{Pages with Borders}
Page borders are rendered on most pages where a current chapter is
defined. Part splash pages is an example where they are not printed,
and everything up to and including the TOC will be borderless.
Another example is when starting a new part, but not a new chapter,
which will signal that no border should be rendered.
Image pages are borderless by
default, but this can be controlled with options (see
p.~\pageref{sec:imagepage}).

The borders will have the chapter number, a cross, followed by the
chapter title. Page numbers will always be printed, irrespective of
whether a border is rendered or not.

The mode colour might have poor contrast with the borders, so a specific
colour can be used for both page numbers and border text for all pages
with rendered border. If unset, the mode colour will be used. See
table below. The Astro Inferno Core Rulebook always uses white border
text and page numbers for all pages with borders.

\section{Transparency}
All three box environments can be made semitransparent by passing the
option |opacityfill=O|, where |O| $\in$ [0, 1]. See |tcolorbox| package documentation
for more precise control over transparency of different elements.

\begin{AIComment}[opacityfill=0.5]{You can see right through me!}
  This comment box was made with |opacityfill=0.5|.
  The text remains opaque.
\end{AIComment}

\section{Box Styles}
Boxes (p.~\pageref{ch:text_boxes}) can be modified by passing |tcolorbox| options
(see the |tcolorbox| package documentation). To facilitate customisation of boxes
there are a number of predefined box style modules that can be assigned to specific box types.

The box styles can be set with |\AICommentAddBoxstyle{}| (or corresponding commands for the other box types),
which will affect all subsequent boxes of that type.
|\AICommentClearBoxstyle| clears the box style completely, and |\AICommentDefaultBoxstyle| reverts to default.
It is however often more convenient to just pass a box style among the optional arguments to a box, e.g.,
|\begin{AIComment}[AIboxstyleFrame]| to apply it to a single box instance.\footnote{With the current implementation,
    setting a box style with the |...AddBoxstyle| command cannot set the background colour and a few other properties.
    Those can however be set manually via the optional arguments to the box.}
